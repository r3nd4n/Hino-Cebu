# Phase 01.1 Plan 07: Consent-Aware Marketing Boundary Summary

**Optional GTM, GA4, and Meta loading plus typed event dispatch now fail closed behind one granular, versioned browser consent contract.**

## Performance

- **Duration:** 9 min
- **Started:** 2026-08-22T14:36:05Z
- **Completed:** 2026-08-22T14:44:50Z
- **Tasks:** 2
- **Files modified:** 4

## Accomplishments

- Added an exact versioned preference parser that rejects absent, malformed, stale, unknown, and structurally expanded values to immutable analytics/advertising denial.
- Replaced unconditional third-party scripts with one small first-party bootstrap that validates identifiers and creates provider elements only after the required purpose grant.
- Gated `dataLayer` and `gtag` dispatch by analytics consent and `fbq` dispatch by advertising consent while preserving typed events and safe property filtering.
- Added executable VM contracts for negative states, granular grants, invalid identifiers, provider globals, dispatch separation, and single public-shell ownership.

## Files Created/Modified

- `src/lib/analytics.ts` - Applies purpose consent before touching optional provider globals.
- `tests/visual-polish.test.mjs` - Executes provider and dispatch behavior in isolated fixtures and verifies shell ownership.

## Decisions Made

- Grant values use the closed strings `granted` and `denied` at schema version 1; booleans, missing fields, extra fields, and other strings fail closed.
- GA4 may load with analytics-only consent, Meta may load with advertising-only consent, and GTM requires both because its downstream tag mix is not yet governed.
- Validated provider identifiers are serialized as data and URL-encoded; raw environment values never enter executable syntax.
- No visual consent component, implicit opt-in, consent-mode request, provider policy, or withdrawal workflow was added because Phase 3 owns GOV-05 and GOV-06 completion.
