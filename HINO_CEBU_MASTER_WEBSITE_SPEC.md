# 1. Executive Intent

Build a high-performance, modern, local-first website focused on **Hino Cebu** as the digital sales, service, parts, financing, fleet-support, and trust hub for commercial truck buyers and owners in Cebu.

This website must **not** be a clone of the Hino Philippines website.

It may preserve the broad Hino visual family—especially the red / white / black / neutral palette and strong truck-led imagery—but its information architecture, UX, content strategy, conversion architecture, page structure, and local SEO strategy must be original and optimized specifically for the Cebu branch.

The website exists to create measurable commercial outcomes:

1. Generate qualified truck sales inquiries.
2. Generate service booking inquiries.
3. Generate genuine parts inquiries.
4. Generate financing and fleet-support leads.
5. Increase discovery of the Hino Cebu branch in Google Search and Google Maps.
6. Build topical authority for commercial trucks in Cebu.
7. Turn branch activity, deliveries, promotions, and expertise into durable SEO assets.
8. Strengthen Hino Cebu as the locally relevant brand while respecting Hino Philippines as the national brand authority.

The strategic objective is not to "beat Hino Philippines" for corporate brand terms.

The objective is to become the strongest digital answer for **local commercial intent**, including searches such as:

- Hino Cebu
- Hino dealer Cebu
- Hino trucks Cebu
- Hino 300 Cebu
- Hino 500 Cebu
- commercial truck dealer Cebu

- delivery truck Cebu

# 12. Find Your Truck Experience

This feature should be designed as a lead-generation decision tool.

## Initial implementation

Use a lightweight rules-based recommendation engine.

Inputs:

1. Business / industry
2. Cargo type
3. Estimated payload range
4. Preferred body/application
5. Operating environment
6. Fleet size
7. Purchase timeline

Output:

- 1–3 recommended model families
- explanation of why
- caveat that final vehicle suitability requires consultation
- "Request Recommendation / Quote" CTA

## Technical requirement

The rules must be data-driven and easy to edit.

Do not bury recommendation logic in UI components.

Example data structure:

```ts
type TruckRecommendationRule = {
  id: string
  industries: string[]
  payloadRange?: [number, number]
  bodyTypes?: string[]
  modelSlugs: string[]
  rationale: string
}
```

# 25. Performance Requirements

Performance is a marketing requirement.

Targets:

- excellent mobile performance,
- avoid layout shift,
- minimize JavaScript,
- optimize all imagery,
- lazy-load below-the-fold media,
- use responsive images,
- no heavy carousel library unless necessary,
- no unnecessary animation framework,
- avoid auto-playing hero video for launch.

Performance budget concept:

- initial page should remain lean,
- use server components where appropriate,
- client components only when interactivity requires them.

Target WCAG 2.2 AA practices.

Required:

- semantic HTML,
- visible focus states,
- keyboard navigation,
- label every field,
- useful alt text,
- sufficient contrast,
- accessible error messages,
- reduced-motion respect,
- no information conveyed only by color,
- skip-navigation link,
- proper heading hierarchy.

# 47. Hosting, Domain & Cost-Control Doctrine

## Hosting decision

Production hosting is intended for **Vercel**.

This is a commercial dealership website, so deployment planning must use a Vercel plan that permits commercial production use. Do not assume the free Hobby plan is acceptable for the live business website.

The engineering goal is to keep recurring infrastructure spend as low as reasonably possible so that the majority of discretionary marketing budget can be directed toward:

- Google Ads
- Meta Ads
- creative production
- SEO content
- local photography
- conversion optimization

## Domain

The production domain is **TBD**.

All canonical URLs, Open Graph URLs, sitemap URLs, structured-data URLs, redirects, and environment configuration must therefore use an environment-driven site origin.

Required pattern:

```env
NEXT_PUBLIC_SITE_URL=https://example.com
```

Never hardcode the future production domain into page components.

Until the domain is approved:

- use localhost in development,
- use Vercel preview domains for staging,
- avoid publishing hardcoded canonical production URLs,
- keep domain-related configuration centralized.

## Infrastructure cost rules

At MVP, prefer:

1. Static generation where practical.
2. Server rendering only when there is a real requirement.
3. Minimal serverless-function execution.
4. Static images in the repository / public assets when practical.
5. No paid database unless business functionality genuinely requires one.
6. No paid headless CMS at launch.
7. No paid search service.
8. No paid A/B testing platform.
9. No paid chat widget by default.
10. No paid analytics add-on unless it provides measurable value beyond the free marketing stack.

## Initial content-management strategy

For the first production version, prefer a repository-based content system:

- TypeScript data
- JSON
- Markdown / MDX

This avoids unnecessary CMS subscription cost.

The architecture must remain CMS-ready so a non-technical editing layer can be added later once the content volume or staffing justifies the expense.

## Initial media strategy

Prefer optimized static assets deployed with the application.

Do not introduce Vercel Blob or another paid asset-storage layer for ordinary website photography unless:

- asset volume becomes operationally difficult,
- uploads are required,
- or the cost/benefit is approved.

For the MVP, file uploads on service / parts forms may be deferred or feature-flagged until storage and privacy handling are approved.

# 50. Campaign Landing Page Architecture

Do not send every paid campaign to the homepage.

```text
/lp/hino-300-cebu
/lp/hino-500-cebu
/lp/truck-financing-cebu
/lp/hino-service-cebu
/lp/hino-parts-cebu
```

Landing pages should support:

- campaign-specific hero copy
- model / service value proposition
- relevant trust proof
- concise benefits
- FAQs
- short lead form
- phone CTA
- directions CTA where relevant
- campaign attribution
- optional noindex for temporary / duplicated ad variants

Do not create doorway pages solely for SEO.

Paid landing pages may be excluded from organic indexing when they substantially duplicate canonical content.

# 51. Measurement Before Scaling Ads

Paid media should not be scaled until the website can reliably report:

- landing page
- campaign source
- lead type
- lead completion
- phone-click intent
- model / service interest

Recommended operational rule:

> Do not increase ad spend because traffic increased. Increase spend when qualified lead economics justify it.

The website should therefore preserve clean attribution data for future CRM reconciliation and offline conversion tracking.
